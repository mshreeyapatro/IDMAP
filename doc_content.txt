Yes. Since you want to genuinely support those resume bullets, you need to build the following components in IDMAP. You don't need to build a huge ChatGPT-like system; a focused RAG + LLM layer is enough.
1. Core IDMAP ML pipeline
These are the foundation:
.h5 satellite-image loader
Read images from HDF5 using h5py
Inspect dimensions, labels, metadata
Convert to NumPy/PyTorch tensors
Image preprocessing
Resize/normalize images
Handle missing/corrupted samples
Train/validation/test split
Data augmentation if appropriate
CNN models
Train your smaller CNN models on image subsets
Extract meaningful feature vectors from the CNN
Save the trained models/features
Feature/embedding generation
Convert cyclone images/features into numerical embeddings
Store the embeddings with their associated cyclone metadata

2. RAG knowledge base
This is the part you need to add to legitimately call it a RAG pipeline.
Create a knowledge base containing things such as:

5. Connect the CV model to RAG
This is what makes your project more interesting than a generic RAG chatbot.

Convert these model outputs into structured context.

6. LLM layer
The LLM should not make the cyclone prediction itself.
Instead:
ML models → provide predictions
RAG → provides supporting knowledge
LLM → explains the results
For example:
"The model predicts a high-risk situation for coastal Odisha. Similar historical events and the retrieved disaster-management guidelines indicate..."
This is much more defensible academically.

7. Prompt engineering
Create structured prompts containing:
SYSTEM ROLE
You are a cyclone risk analysis assistant.

MODEL OUTPUT
Current risk: High
Forecast: ...
Anomaly score: ...

RETRIEVED CONTEXT
...

TASK
Explain the prediction.
Identify relevant risks.
Provide evidence-based advisory information.
Do not invent information.
You can create separate prompts for:
Risk explanation
Forecast explanation
Historical comparison
District-level advisory
Resource planning
What-if scenarios

8. RAG response validation
This is useful because you can demonstrate that your LLM isn't simply hallucinating.
Check:
Was the answer based on retrieved context?
Were relevant documents retrieved?
Are citations/source references available?
Did the LLM introduce unsupported claims?
You can measure things such as retrieval relevance and response quality.
